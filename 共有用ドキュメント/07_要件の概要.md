# 要件の概要

> 「何のために・だれのために・何を作るか」をまとめたページです。やさしい言葉で書いています。
> （内部向けの詳しい品質方針は別管理です。ここは共有用の概要です。）

## 背景と目的

- スクールでは、講師がすべての受講生の成果物をレビューしきるのは大変です。受講生も「レビューされる経験」「人のコードを読んでレビューする経験」が不足しがちで、学習が孤独になりやすいです。
- そこで、**受講生どうしが成果物をレビューし合い、その積み重ねが一人ひとりの「成長の記録」になる場**を作ります。
- レビューする側の貢献も実績として見えるようにし、参加が続く動機をつくります。

## だれのためか

- スクール内のメンバー限定（**招待制**・クラスの中だけのクローズド）
- 役割は **受講生 / 講師**（将来、管理者などへ広げられる設計）
- 利用者は **クラス（期）** に所属します

## 似たサービスとのちがい（差別化）

世の中の「レビュー SNS」や「コードレビュー道具」とは、ねらいが違います。

| 観点 | よくあるレビュー SNS / 一般のレビュー道具 | レビューラボ |
|---|---|---|
| 主役 | 投稿とやり取りそのもの | **一人ひとりの「成長の記録」** |
| レビューする人 | 評価されない | **「したレビュー」も実績になる**（参加が続きやすい） |
| レビューの中身 | 自由記述で空疎になりがち | **観点ごとの枠で構造化**（建設的・学びにつながる） |
| 講師の関わり | ない / 一律 | **講師レビューを特別表示＋最終評価・合格バッジ** |
| 公開範囲 | だれでも見られる | **クラスの中だけ（クローズド）** |

- 仕事向けのコードレビュー（チームの PR レビューなど）は「成果物を通すこと」が主目的ですが、
  レビューラボは**学びと成長の積み重ね**が目的です。
- 「読む側・読まれる側」の両方を実績にすることで、レビューが一部の人に偏らず、
  みんなで続けられる設計にしています。

## いちばん力を入れている点

このサービスの肝は「安心してお互いの成果物を見せ合える、信頼できる場」です。
クローズドで複数の役割があり、他人の成果物も見られる――この構造だからこそ、
**「だれが・何に・どの操作をできるか」を正しく制御すること**が、品質のいちばんの決め手になります。

目指すこと（できるだけ測れる形で）：

- すべての操作で「他人や他クラスの情報にアクセスできない」ことを自動テストで確かめる
- 使っている部品の弱点（脆弱性）を継続的にチェックし、重大なものは無い状態を保つ
- 「だれが・何に・どんな権限を持つか」を文書にまとめておく
- 「だれが・いつ・何にアクセスしたか」を記録できるようにする

## 品質の最低ライン

上の点を最重視しつつ、ほかの観点（安定して動く・直しやすい・使いやすい・十分に速い）も
**すべて一定の水準以上**を保つようにします。
ひとつを良くするために、ほかを大きく犠牲にしないことを大切にします
（例：権限チェックを増やしても、体感の速さを落とさない）。

## 主な機能（段階的に作る）

### 第1段階（最小のひと回り）

- ログイン（招待制・役割つき）
- 成果物の投稿（URL・スクリーンショット・説明）
- レビュー（観点別コメント＋「良かった点 / もっと良くなる点」、「ありがとう」）
- 講師の最終評価（合格 / 差し戻し、合格バッジ）
- 成長の記録ページ（投稿・もらった / したレビュー・実績）

### 第2段階（質を高める）

- レビューへの返信、検索・絞り込み、通知、継続記録 など

### 将来

- 外部サービス連携、複数クラスの運用、コードの行単位コメント など

## だれが何をできるか（ざっくり）

- 受講生：投稿・レビュー・自分のものの編集 / 削除・成長の記録
- 講師：上に加えて「最終評価（合格 / 差し戻し）」
- 管理者：クラス作成・アカウント発行・招待
- 共通ルール：他人や他クラスの情報には触れない（くわしくは「権限と安全の考え方」を参照）

## 前提・制約

- 個人開発のプロジェクトです（当面は本格運用しない。将来の実運用は可能性として残す）。
- コストは低く抑えます（無料枠を中心に）。
- パスワードや鍵などの機密はコードに書きません。
- いまは簡素にしている部分があります（冗長化など）。本格運用に移る際に見直します。

## いまは作らないもの（対象外）

- 外部公開 / SEO、リアルタイム通信、ネイティブアプリ、コードの行単位コメント など

## まとめ

- 受講生どうしのレビューで「成長の記録」を積み上げる場
- いちばんの肝は「だれが何にアクセスできるか」を正しく守ること
- 機能は段階的に。個人開発のクローズドな運用
