# HTTPS（TLS）設定の手順 — 無料ドメイン＋無料証明書

> このページは、サイトを「鍵マーク付きの安全な通信（HTTPS）」で公開するための手順です。
> むずかしい言葉が出てきますが、ひとつずつやさしく説明します。

## まず用語をやさしく

- **HTTPS / TLS**：ブラウザとサーバーの通信を暗号化するしくみ。これが無いと、ブラウザに「保護されていない通信」と警告が出ます。
- **証明書（サーバー証明書）**：「このサイトは本物です」と証明する電子的な書類。信頼された発行元から取得します。
- **Let's Encrypt**：証明書を**無料**で発行してくれる団体。多くのサイトで使われています。
- **ドメイン**：`example.com` のような住所。証明書はドメインに対して発行されます。
- **動的 DNS（DuckDNS など）**：無料でサブドメインをもらい、自分のサーバーの IP アドレスに結びつけられるサービス。

つまり流れは「ドメインをもらう → サーバーに向ける → 証明書を取る」です。

## 全体像

```
ブラウザ ──HTTPS（鍵マーク）──▶ サーバー（受付の nginx）──▶ アプリ
                 ▲
        Let's Encrypt の証明書
```

## 手順

### 1. サブドメインを用意してサーバーに向ける

1. 動的 DNS サービスでサブドメインを作成します（例：`<あなたのドメイン>`）。
2. そのサブドメインを、サーバーの IP アドレス（`<サーバーのIP>`）に結びつけます。
3. 反映には少し時間がかかることがあります（数分）。`<あなたのドメイン>` が IP を返すようになってから次へ進みます。

> 注意：サービスによってサブドメイン名に使える文字が決まっています（英数字とハイフンのみ等）。記号は使えないことが多いです。

### 2. サーバー側でセットアップを実行する

サーバーに安全な経路でログインし、用意してあるセットアップ用スクリプトを「ドメイン指定モード」で実行します。
このスクリプトが次をまとめて行います。

- 受付（nginx）をそのドメイン向けに設定する
- 証明書取得ツール（certbot）で Let's Encrypt の正式な証明書を取得する
- HTTP（暗号化なし）でアクセスが来たら HTTPS（暗号化あり）へ自動で転送する設定にする

> 前提：サーバーの 80 番・443 番ポートが外から届くこと、ドメインが正しく IP を指していること。
> どちらかが未完了だと証明書の取得に失敗します。

### 3. 正しく設定できたか確認する

ブラウザとコマンドで次を確認します。

- ブラウザで開いて**鍵マークが付き、警告が出ない**こと
- `http://` で開くと自動で `https://` に変わること（恒久リダイレクト）
- ログインしていない状態で保護された API を叩くと「未認証」で弾かれること
- 稼働確認用のエンドポイントが「正常」を返すこと

### 4. 証明書の自動更新

Let's Encrypt の証明書には有効期限（おおよそ 90 日）があります。
セットアップ時に**自動更新のタイマー**が入るので、期限が近づくと自動で更新されます。
基本は放っておいて大丈夫ですが、ときどき「更新が動いているか」を確認すると安心です。

## うまくいかないときに戻すには

ドメイン設定で問題が起きた場合は、ドメインを使わない以前の設定（自己署名の暫定 HTTPS など）に戻して、
サイト自体は動かし続けられるようにしておきます。原因（DNS の反映待ち・ポート・権限）を切り分けてから再挑戦します。

## まとめ

1. サブドメインをもらってサーバーの IP に向ける
2. サーバーでセットアップ（nginx 設定＋証明書取得＋HTTP→HTTPS 転送）
3. 鍵マーク・リダイレクト・健康チェックで確認
4. 証明書は自動更新に任せる
